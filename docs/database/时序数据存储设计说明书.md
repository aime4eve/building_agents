## 1. 概述

### 1.1 背景

华宽通智能体系统支持21类物联网设备，这些设备产生的遥测数据具有明显的时序特征：
- 数据按时间顺序追加
- 数据写入量大，查询通常是按时间范围
- 数据通常不需要修改，主要用于趋势分析
- 历史数据有一定的保留周期

### 1.2 设计目标

| 目标 | 说明 |
|------|------|
| 高写入性能 | 支持每秒数千条数据写入 |
| 高效查询 | 按时间范围、设备ID快速查询 |
| 数据压缩 | 自动压缩历史数据，节省存储空间 |
- 水平扩展 | 支持数据分片和集群部署 |

### 1.3 存储选型

| 数据库 | 优势 | 劣势 | 推荐场景 |
|--------|------|------|----------|
| **InfluxDB** | 专为时序数据设计，性能优异，生态丰富 | 单节点写入有限，集群版收费 | 中小规模部署，推荐用于Phase 1 |
| **TDengine** | 国产开源，性能强劲，支持SQL | 生态相对较新 | 大规模部署，有国产化需求 |
| **TimescaleDB** | 基于PostgreSQL，SQL支持完整 | 压缩比不如专业时序库 | 需要复杂SQL分析的场景 |

**推荐方案：Phase 1 使用 InfluxDB 2.x**

## 2. InfluxDB 设计

### 2.1 数据组织结构

InfluxDB 使用 **Bucket -> Measurement -> Tag/Field** 的数据模型：

```
Bucket (hkt_iot)
├── device_telemetry (设备遥测数据)
│   ├── Tags: device_id, tenant_id, device_type, space_id
│   └── Fields: temperature, humidity, power, ...
├── device_event (设备事件数据)
│   ├── Tags: device_id, tenant_id, device_type, event_type, event_level
│   └── Fields: event_data, metadata
└── device_status (设备状态变更历史)
    ├── Tags: device_id, tenant_id, device_type, status
    └── Fields: reason, duration
```

### 2.2 Bucket 设计

| Bucket | 保留策略 | 分片时长 | 说明 |
|--------|----------|----------|------|
| hkt_iot_raw | 30天 | 1天 | 原始遥测数据 |
| hkt_iot_downsample_1h | 365天 | 30天 | 1小时聚合数据 |
| hkt_iot_downsample_1d | 5年 | 365天 | 1天聚合数据 |
| hkt_iot_event | 90天 | 7天 | 设备事件数据 |
| hkt_iot_status | 7天 | 1天 | 设备状态历史 |

### 2.3 Measurement 设计

#### 2.3.1 device_telemetry (设备遥测数据)

**Tags（索引字段）：**
```
- device_id: string      # 设备ID
- tenant_id: string      # 租户ID
- device_type: string    # 设备类型
- space_id: string       # 空间ID（可选）
- location: string       # 位置标签（可选）
```

**Fields（数据字段）：**
```
# 温度传感器
- temperature: float     # 温度值（℃）

# 湿度传感器
- humidity: float        # 湿度值（%）

# 水表
- total_volume: float    # 累计用水量（升）
- flow_rate: float       # 流速（升/分钟）

# 电表
- total_energy: float    # 累计用电量（kWh）
- voltage: float         # 电压（V）
- current: float         # 电流（A）
- power: float           # 功率（W）

# 气表
- gas_volume: float      # 累计用气量（m³）
- pressure: float        # 压力（Pa）

# 门磁/地磁等
- status: boolean        # 状态（开/关，检测到/未检测到）
- duration: long         # 持续时间（秒）

# 通用元数据
- battery: integer       # 电池电量（%）
- rssi: integer          # 信号强度（dBm）
```

**Timestamp：**
```
- _time: timestamp       # 数据上报时间（自动）
```

#### 2.3.2 device_event (设备事件数据)

**Tags：**
```
- device_id: string
- tenant_id: string
- device_type: string
- event_type: string     # 事件类型
- event_level: string    # INFO/WARN/ERROR
```

**Fields：**
```
- event_data: string     # 事件数据（JSON）
- metadata: string       # 元数据（JSON）
```

#### 2.3.3 device_status (设备状态历史)

**Tags：**
```
- device_id: string
- tenant_id: string
- device_type: string
- status: string         # ONLINE/OFFLINE/FAULT/MAINTENANCE
```

**Fields：**
```
- reason: string         # 状态变更原因
- duration: long         # 持续时长（秒）
```

### 2.4 数据写入示例

**写入遥测数据：**
```javascript
// 使用 InfluxDB Line Protocol
device_telemetry,device_id=dev_001,tenant_id=tenant_001,device_type=temperature_sensor temperature=25.5,humidity=60.2,battery=85 1708416000000000000
```

**使用 Flux 写入：**
```javascript
import "influxdata/influxdb/schema"

option task = {name: "device_telemetry", every: 1s}

data = {
  "device_id": "dev_001",
  "tenant_id": "tenant_001",
  "device_type": "temperature_sensor",
  "temperature": 25.5,
  "humidity": 60.2,
  "battery": 85
}

to(bucket: "hkt_iot_raw", org: "hkt_iot", timeColumn: "_time")
  |> experimental.to(quantity: data)
```

### 2.5 数据查询示例

**查询单设备最近1小时数据：**
```flux
from(bucket: "hkt_iot_raw")
  |> range(start: -1h)
  |> filter(fn: (r) => r["_measurement"] == "device_telemetry")
  |> filter(fn: (r) => r["device_id"] == "dev_001")
  |> filter(fn: (r) => r["_field"] == "temperature" or r["_field"] == "humidity")
```

**查询多设备聚合数据：**
```flux
from(bucket: "hkt_iot_raw")
  |> range(start: -24h)
  |> filter(fn: (r) => r["_measurement"] == "device_telemetry")
  |> filter(fn: (r) => r["tenant_id"] == "tenant_001")
  |> filter(fn: (r) => r["_field"] == "temperature")
  |> aggregateWindow(every: 1h, fn: mean, createEmpty: false)
  |> group(columns: ["device_id"])
```

**查询设备状态变更历史：**
```flux
from(bucket: "hkt_iot_status")
  |> range(start: -7d)
  |> filter(fn: (r) => r["_measurement"] == "device_status")
  |> filter(fn: (r) => r["device_id"] == "dev_001")
  |> sort(columns: ["_time"])
```

### 2.6 数据降采样（Downsampling）

使用 InfluxDB Tasks 自动进行数据降采样：

**1小时聚合任务：**
```flux
option task = {
  name: "downsample_1h",
  every: 1h,
  offset: 10m
}

raw_data = from(bucket: "hkt_iot_raw")
  |> range(start: -1h)
  |> filter(fn: (r) => r["_measurement"] == "device_telemetry")

// 对数值字段计算平均值、最大值、最小值
numeric_fields = raw_data
  |> filter(fn: (r) => r["_value"] exists)
  |> aggregateWindow(
    every: 1h,
    fn: (tables) =>
      tables
        |> mean(column: "_value")
        |> set(key: "_field", value: "${_field}_mean")
    |> or(tables => tables |> max(column: "_value") |> set(key: "_field", value: "${_field}_max"))
    |> or(tables => tables |> min(column: "_value") |> set(key: "_field", value: "${_field}_min")),
    createEmpty: false
  )

to(bucket: "hkt_iot_downsample_1h", org: "hkt_iot")
  |> timeShift(duration: 1h)
  |> numeric_fields
```

### 2.7 连续查询（Continuous Queries）

```flux
// 实时计算设备在线率
option task = {name: "device_online_rate", every: 5m}

from(bucket: "hkt_iot_status")
  |> range(start: -5m)
  |> filter(fn: (r) => r["_measurement"] == "device_status")
  |> filter(fn: (r) => r["_field"] == "duration")
  |> group(columns: ["tenant_id", "status"])
  |> sum(column: "_value")
  |> yield(name: "online_rate")
```

## 3. TDengine 设计

### 3.1 数据库设计

TDengine 使用 **Database -> Stable -> Table** 的模型：

```
Database (hkt_iot)
├── device_telemetry_stable (超级表)
│   ├── 表: dev_001, dev_002, ... (每个设备一张子表)
│   └── 字段: ts, temperature, humidity, power, ...
├── device_event_stable (超级表)
│   ├── 表: dev_001_events, dev_002_events, ...
│   └── 字段: ts, event_type, event_level, event_data
└── device_status_stable (超级表)
    ├── 表: dev_001_status, dev_002_status, ...
    └── 字段: ts, status, reason, duration
```

### 3.2 超级表（Stable）设计

#### 3.2.1 device_telemetry_stable

```sql
CREATE STABLE device_telemetry_stable (
    ts TIMESTAMP,                    -- 时间戳
    temperature FLOAT,               -- 温度
    humidity FLOAT,                  -- 湿度
    total_volume FLOAT,              -- 累计用水量
    flow_rate FLOAT,                 -- 流速
    total_energy FLOAT,              -- 累计用电量
    voltage FLOAT,                   -- 电压
    current FLOAT,                   -- 电流
    power FLOAT,                     -- 功率
    gas_volume FLOAT,                -- 累计用气量
    pressure FLOAT,                  -- 压力
    status BOOL,                     -- 状态
    duration BIGINT,                 -- 持续时长
    battery INT,                     -- 电池电量
    rssi INT                         -- 信号强度
) TAGS (
    device_id NCHAR(50),             -- 设备ID
    tenant_id NCHAR(50),             -- 租户ID
    device_type NCHAR(50),           -- 设备类型
    space_id NCHAR(50),              -- 空间ID
    location NCHAR(100)              -- 位置
);
```

#### 3.2.2 device_event_stable

```sql
CREATE STABLE device_event_stable (
    ts TIMESTAMP,
    event_type NCHAR(50),            -- 事件类型
    event_level NCHAR(20),           -- 事件级别
    event_data NCHAR(1000),          -- 事件数据（JSON）
    metadata NCHAR(500)              -- 元数据（JSON）
) TAGS (
    device_id NCHAR(50),
    tenant_id NCHAR(50),
    device_type NCHAR(50)
);
```

#### 3.2.3 device_status_stable

```sql
CREATE STABLE device_status_stable (
    ts TIMESTAMP,
    status NCHAR(20),                -- 状态
    reason NCHAR(200),               -- 原因
    duration BIGINT                  -- 持续时长
) TAGS (
    device_id NCHAR(50),
    tenant_id NCHAR(50),
    device_type NCHAR(50)
);
```

### 3.3 创建子表

```sql
-- 为设备创建子表（自动）
CREATE TABLE IF NOT EXISTS dev_001 USING device_telemetry_stable
TAGS ('dev_001', 'tenant_001', 'temperature_sensor', 'space_001', '1F-走廊');

CREATE TABLE IF NOT EXISTS dev_001_events USING device_event_stable
TAGS ('dev_001', 'tenant_001', 'temperature_sensor');

CREATE TABLE IF NOT EXISTS dev_001_status USING device_status_stable
TAGS ('dev_001', 'tenant_001', 'temperature_sensor');
```

### 3.4 数据写入

```sql
-- 写入遥测数据
INSERT INTO dev_001 VALUES (NOW, 25.5, 60.2, NULL, NULL, NULL, NULL, NULL, NULL, NULL, NULL, NULL, NULL, 85, -65);

-- 使用 NCHAR 字段
INSERT INTO dev_001_events VALUES (NOW, 'alarm', 'ERROR', '{"alarmType":"high_temp","value":35.5}', '{"battery":80}');

-- 批量写入
INSERT INTO dev_001 VALUES
    (NOW - 10s, 25.3, 60.1, NULL, NULL, NULL, NULL, NULL, NULL, NULL, NULL, NULL, NULL, 85, -65)
    (NOW - 5s, 25.4, 60.2, NULL, NULL, NULL, NULL, NULL, NULL, NULL, NULL, NULL, NULL, 85, -65)
    (NOW, 25.5, 60.3, NULL, NULL, NULL, NULL, NULL, NULL, NULL, NULL, NULL, NULL, 85, -65);
```

### 3.5 数据查询

```sql
-- 查询单设备最近1小时数据
SELECT * FROM dev_001 WHERE ts > NOW - 1h;

-- 查询多设备最新数据
SELECT last_row(*) FROM device_telemetry_stable
WHERE tenant_id = 'tenant_001'
GROUP BY device_id;

-- 按时间窗口聚合
SELECT _wstart, _wend, AVG(temperature) AS avg_temp, MAX(temperature) AS max_temp
FROM device_telemetry_stable
WHERE device_id = 'dev_001' AND ts > NOW - 24h
INTERVAL(1h);

-- 查询设备状态变更
SELECT * FROM device_status_stable
WHERE device_id = 'dev_001' AND ts > NOW - 7d
ORDER BY ts DESC;
```

### 3.6 数据保留策略

```sql
-- 修改数据库保留时间
ALTER DATABASE hkt_iot KEEP 30;  -- 保留30天

-- 创建连续查询，自动降采样
CREATE CONTINUOUS QUERY cq_1h_avg ON hkt_iot
BEGIN
    SELECT AVG(*) INTO hkt_iot_history.device_telemetry_stable_1h
    FROM device_telemetry_stable
    WHERE ts > NOW - 1h
    INTERVAL(1h) SLIDING(1h);
END;
```

## 8. 性能优化建议

### 8.1 写入优化

1. **批量写入**：每次写入100-1000条数据
2. **异步写入**：使用消息队列缓冲
3. **合理分片**：按设备ID分布数据

### 8.2 查询优化

1. **使用 Tag 过滤**：减少扫描数据量
2. **限定时间范围**：避免全表扫描
3. **使用降采样数据**：历史查询使用聚合数据

### 8.3 存储优化

1. **数据压缩**：启用数据库压缩功能
2. **数据分级**：热数据、温数据、冷数据分离
3. **定期归档**：超期数据迁移到冷存储
